# Data Model: Migrate SSH Settings from Deprecated MatchBlocks

**Branch**: `009-migrate-ssh-settings` | **Date**: 2026-10-12 | **Spec**: [spec.md](spec.md)

This document formalizes the entities, schema definitions, attribute mappings, and validation constraints for the SSH configuration migration.

---

## 1. Entities & Configuration Schemas

### Entity 1: SSH Service Feature Module (`modules/services/ssh.nix`)
Represents the dendritic feature module declaring both the NixOS OpenSSH daemon settings and the Home Manager user-level SSH client configuration.

| Scope | Option / Attribute | Type / Schema | Purpose |
|---|---|---|---|
| **Dendritic Identification** | `flake.modules.services.ssh` | Attrset `{ nixos, homeManager }` | Exported module discovered via `import-tree` |
| **NixOS Daemon** | `nixos.services.openssh.enable` | `bool` (`true`) | Enable system OpenSSH server |
| | `nixos.services.openssh.settings` | Attrset | Server security options (PermitRootLogin, PasswordAuthentication, etc.) |
| | `nixos.services.openssh.openFirewall` | `bool` (`true`) | Allow incoming SSH traffic through firewall |
| **Home Manager Client** | `homeManager.programs.ssh.enable` | `bool` (`true`) | Enable user OpenSSH client management |
| | `homeManager.programs.ssh.enableDefaultConfig` | `bool` (`false`) | Disable default Home Manager wildcard host block |
| | `homeManager.programs.ssh.settings` | `attrsOf (submodule with freeformType)` | Declarative OpenSSH client host blocks (replaces `matchBlocks`) |

---

### Entity 2: SSH Host Configuration Profile (`programs.ssh.settings.<alias>`)
Represents a declarative host alias profile defining parameters for connecting to a specific remote machine.

| Attribute | Schema Type | Value (`rpi3`) | Value (`homelab-vm`) | Output Directive |
|---|---|---|---|---|
| **Header Key** | `str` | `"rpi3"` | `"homelab-vm"` | `Host <alias>` |
| `HostName` | `str` | `"192.168.1.68"` | `"192.168.1.194"` | `HostName <ip>` |
| `User` | `str` | `"pi"` | `"core"` | `User <username>` |
| `IdentityFile` | `str` | `"~/.ssh/id_ed25519"` | `"~/.ssh/id_ed25519"` | `IdentityFile <path>` |
| `CheckHostIP` | `bool` | `false` | `false` | `CheckHostIP no` |

#### Validation Constraints
1. **Key Naming**: Keys must use canonical OpenSSH PascalCase directive names (`HostName`, `User`, `IdentityFile`, `CheckHostIP`).
2. **Boolean Mapping**: `CheckHostIP = false` must evaluate to `CheckHostIP no` in the generated configuration text.
3. **No Deprecated Directives**: Must not use lowercase option names from legacy `matchBlocks` (`hostname`, `user`, `identityFile`, `checkHostIP`).

---

### Entity 3: Generated Client SSH Configuration File (`~/.ssh/config`)
Represents the target physical configuration file generated by Home Manager from `programs.ssh.settings`.

```text
Host rpi3
  CheckHostIP no
  HostName 192.168.1.68
  IdentityFile ~/.ssh/id_ed25519
  User pi

Host homelab-vm
  CheckHostIP no
  HostName 192.168.1.194
  IdentityFile ~/.ssh/id_ed25519
  User core
```

#### Field Specifications & Invariants
- **Block Header**: Each block begins with `Host <alias>`.
- **Indentation**: Sub-directives are indented by two spaces (`  `).
- **Directive Ordering**: Directives within a host block are sorted by directive name (with `IgnoreUnknown` prioritized if present).
- **Wildcard Block**: No wildcard `Host *` block is present when `enableDefaultConfig = false` and no `"*"` key is defined in `settings`.
